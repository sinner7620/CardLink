# 同脑图答案匹配与悬浮球快捷功能区实现方案

状态：快捷功能区已有胶囊布局、父节点筛选和选中范围的直接子卡遮罩。尚未加入颜色设置界面及「查找答案」的同脑图匹配分支。依据 CardMask v0.1.0 源码及当前 CardLink 代码（2026-09-24）。

## 目标与用户流程

1. 点击全局悬浮球，展开胶囊快捷功能区。图标打开插件页面，开始胶囊启动／停止刷题；第二排在「筛选／全选」之间切换。展开时可拖动快捷区；关闭通过胶囊尾部关闭热区执行。拖动脑图不触发快捷区关闭。
2. 筛选区列出当前脑图按父节点组织的卡片树，逐项选择刷题范围；未配置颜色时显示全部颜色卡片。后续颜色设置界面保存 `colorIndex` 到当前脑图范围，配置后列表按该颜色过滤。
3. 点击「开始刷题」时，插件把选中卡片视为题目，把各题目的**直接子卡片**视为答案；对答案卡片加遮罩。启动时需要当前选中卡片作 Canvas 标定。停止、关闭学习集或场景断开时立即移除遮罩。
4. 已有的「查找答案」也能在同脑图模式下返回当前题目的直接子卡片；答案浮窗沿用现有展示能力。该模式与跨脑图的标题、顺序、正则匹配并列，不改写已有绑定。

「开始刷题」在本方案中指 CardMask 式遮盖当前脑图的答案，区别于工作台现有的错题「复习模式」。首次实现不加入上一题、下一题或复习评分。

## 源码依据与现状

- CardMask 的 `main.js`：从 `mindmapView.selViewLst` 的单选卡读取 `noteId`、`colorIndex`；扫描 `mindmapNodes` 中同色题目及其直接子卡；用 `MindMapNode.frame` 和选中卡校准 Canvas 坐标；每约 0.16 秒同步遮罩。源码声明仅支持直接子卡，重入或切换学习集需重取锚点。
- 当前全局悬浮球在 `src/mnutils-entrance.ts`，单击直接切换 Web 插件页面；拖动停靠、位置持久化和长按复位已有实现。`src/floating-toolbar.ts` 是选卡旁的查找答案/标记错题栏，属于另一入口。
- 现有 `BindingTarget` 只记录答案目标脑图和 `title | parent-order | regex`；`bindAnswerNotebook` 排除了来源脑图本身。`findAnswersForQuestion` 在目标答案索引上查找，当前没有同脑图直接子卡分支。
- 悬浮球曾因单击专属原生菜单出现崩溃面，后来改为直接复用面板开关。重新加入快捷区时，原生视图和手势需单独做真机验证；不能把旧实现视为可直接恢复。

## 数据与匹配契约

- 新增独立的同脑图配置，例如 `SameMindMapPracticeConfig { notebookId, rootNodeId, questionColorIndex }`，键沿用现有脑图范围语义。`colorIndex` 必须按有限整数读取，`0` 是合法颜色，不能用真值判断。配置只保存颜色和范围；Canvas、遮罩、选卡锚点只存本次运行内存。
- 同脑图模式作为**来源脑图的匹配方式**明确选择，不伪造一个指向自身的 `BindingTarget`。现有跨脑图绑定保留；启用新方式时按当前来源范围优先读取同脑图配置，切回原方式后继续使用旧绑定。设置页面显示当前方式和颜色，并提供更换/解除颜色的入口。
- 题目集合：当前脑图范围内 `colorIndex === questionColorIndex` 的真实卡片。答案集合：这些题目节点的直接子卡片。匹配与遮罩共用一个结构收集函数，按节点/笔记 ID 去重并校验仍属于同一脑图；无题目、无子卡、失效节点分别给出明确状态。子孙更深层级不自动纳入。
- 查找答案时以所选题目节点的**直接子节点**返回答案候选，不再做标题回退。一个题目有多个直接子卡时保留多个候选并沿用答案窗口切换。所选卡不是已识别题目时给出提示；避免把答案卡当题目再次匹配。
- 原有错题范围排除、来源定位、答案索引与 `answerOnlyBindingScopes` 需在实现时逐一检查：同脑图下题目和答案共享范围，不能把整棵脑图标成“纯答案范围”。

## 快捷功能区

- 在 `mnutils-entrance.ts` 抽离快捷区视图/状态模块。悬浮球点击只切换快捷区；「打开插件页面」调用现有面板显隐入口并刷新插件命令状态。功能区放在悬浮球朝屏幕内部的一侧，依据可用宽高翻转或收缩，避免越界。
- 筛选列表在没有颜色配置时显示所有颜色卡片；「开始刷题」要求至少选中一个有直接子卡答案的题目，并有当前脑图选中卡用于标定。运行中显示「停止刷题」。未满足条件时提示具体缺项。
- 快捷区拖动保持展开，脑图区域触摸不被快捷区占据；关闭学习集、场景断开时清理快捷区和遮罩。长按复位时继续抑制随后产生的单击。
- 优先采用当前 MNButton 所属窗口的原生控件；先在目标 MarginNote 版本上做最小原型，确认点击、长按、拖动、窗口层级和旋转布局稳定，再完成样式。原生控件释放与重建跟随现有入口生命周期。

## 遮罩实现

- 从 CardMask 提炼“颜色/直接子卡识别”和“Canvas 坐标校准/遮罩同步”，不要直接并入其 `JSB.newAddon`：CardLink 已有自己的插件实例与生命周期。
- 运行前使用当前选中题目作为锚点，计算 `MindMapNode.frame` 到稳定 Canvas 的坐标变换；遮罩为不拦截触摸的原生视图。优先验证 CardMask 的 Canvas 候选 2 与手写层级；候选 1 仅在实际可用且视觉验收通过时使用，不能只凭候选序号保证正确。
- 遮罩按答案节点身份复用，同步卡片增删及布局变化。优先接入已有布局/脑图事件；若事件覆盖不了拖动、缩放或重排，再用受控定时同步，并在停止/切换/断开时取消后续轮次和清理视图。Canvas 丢失或锚点失效时停止刷题并提示重新绑定/启动，不让答案处于半遮盖状态。
- 边界：遮罩只影响当前可见脑图；答案浮窗展示、手写、点击卡片、拖动脑图仍要可用。题目或答案跨脑图链接、复制/别名节点和脑图重排需以真机样本确认节点身份和范围判断。

## 实施顺序与验收

1. **快捷入口与刷题**：胶囊布局、显隐动画、层级选择、直接子卡遮罩和生命周期清理已接入。颜色设置界面尚未加入，未配置时显示所有颜色卡片。MarginNote 真机的点击、滚动、拖动、遮罩位置和手写层级仍需验收。
2. **同脑图匹配**：加入独立配置、直接子卡收集与 `findAnswersForQuestion` 路由；补充颜色 `0`、多答案、无子卡、跨范围、旧绑定保留的行为测试。更新设置页和相关接口文档。
3. **刷题遮罩**：接入 Canvas 校准、遮罩同步和生命周期清理；桌面自动化验证纯数据与状态机，MarginNote 真机验证遮盖准确性、手写层级、交互、拖动缩放及大脑图性能。
4. 按仓库流程对最终代码运行 `pnpm check`、相关测试；涉及 Web/原生资源打包时运行构建。若交付安装包，再按版本、全套检查、复制与哈希流程执行。

## 待真机确认的实现条件

- CardMask 已在其环境观察到候选 2 稳定，CardLink 的目标 MarginNote 版本、iPad/Mac 布局和多窗口场景仍需复测。
- 大脑图下逐帧扫描 `mindmapNodes` 与每 0.16 秒更新原生视图的开销需要量测；最终同步策略按量测结果确定。
- MarginNote 对同一笔记的复制节点、手写层、缩放后 frame 更新时机的行为，须用含这些结构的样本脑图验收。
