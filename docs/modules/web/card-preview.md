# CardPreview — 题目与答案的共享预览入口

## 职责

web/src/CardPreview.jsx管理iframe装载、缩放工具同步和事件清理。src/card-preview.ts的mountCardPreview拥有内容布局、缩放范围、滚动锚点；src/pinch-zoom.ts拥有单指/双指/gesture仲裁。renderCardHtml序列化同一控制器进入原生答案WebView。

## 边界

同一文档只允许一个控制器，禁止父iframe重复接管body缩放。所有交互预览60%—300%，单指原生滚动；导出预览是静态纸张布局，不绑定手势。原题首次高度缓存保留，列表架构改造待审批。

缩小到100%以下时，内容在有余量的方向居中；长内容仍从顶部开始并保留滚动。缩放锚点计入居中偏移。

错题详情、待复习原题预览和原生答案窗口只读加载卡片绑定的脑图手写。个性设置默认“双击显示”：初始隐藏，预览文档内双击或双轻点切换；选择“始终显示”则直接展开且双击不再隐藏。单指拖动与双指缩放不触发切换；无绑定、接口不支持和读取失败显示对应状态。设置变更会重新读取当前错题详情，原生答案窗口下次查找时应用。AI 内容提取不走该交互显示设置，发送策略保持原行为。

摘录图片、PaintNote 和 LinkNote 的配对 paint/drawing 使用同一叠加容器；画布按底图原始尺寸绘制，随图片等比缩放。只有笔迹而无底图的数据仍独立展示，不推测无关联媒体之间的叠加关系。脑图绑定手写作为独立区域展开，不推测其相对整张卡片的脑图坐标。

## 验收

tests/card-preview.test.ts覆盖幂等、清理、单指与双指、打包序列化、浅色与手写DPR比例；浏览器验证缩放时外层答案窗口尺寸不变。

## 原题子卡片控制

`renderCardHtml` 新增可选 `includeChildren` 参数，默认 `true`，保持答案窗口和其他调用方的渲染兼容。错题原题出口根据当前答案绑定决定是否传 `false`：只有题目颜色符合子卡答案配置且没有独立答案脑图时隐藏子卡，混合模式同样适用。`CardPreview` 将 iframe 内完成的点击转为宿主冒泡事件 `cardlink-preview-click`，自动隐藏列表据此收起，不覆盖或吞掉原点击。
