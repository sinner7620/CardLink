# web/src/lib/reviewDetailCache

## 职责

待复习原题与答案各自使用同一种请求协调器。批量展开原题走轻量
`mistakeQuestion` 协议，仅在点击“查看答案”时才调用完整 `mistakeDetail`；
协调器负责请求去重、并发限制和有界缓存。

## 边界

- 同一 `recordId + version` 只保留一个在途 Promise。
- 最多两个原生桥请求并发。
- 默认最多保留 6 项、合计约 8 MB HTML；超限按 LRU 淘汰。
- `clear()` 使当前缓存代失效，但不会试图取消已经进入原生侧的桥请求。
- 单题请求失败会释放并发槽位；页面显示失败态和“重试”，不会永久保留加载文案。
- 已发出的原题请求不会因为筛选、折叠或列表刷新而丢弃回包状态。

## 验收

- 相同请求只调用一次获取函数。
- 四个同时请求的峰值并发不超过两个。
- 超过条目上限后最早且未再次访问的条目被淘汰。
