# MN5 场景模式的折叠优先脑图书写

MN5 场景模式下，沿用「脑图书写」入口。题目的直接子卡承载答案时，CardLink 在进入该题之前先折叠题卡分支，确认收起后再允许作答。用户主动查看时按现有设置展开分支或打开答案窗口。此方案覆盖共用脑图书写流程的做题与复习，沿用原有题目队列、标记和评分规则。

## 启用条件

| 当前题目与宿主 | 脑图书写行为 |
| --- | --- |
| MN5 场景已启用、当前面板已授权且支持分支折叠，题卡分支可以整体收起 | 折叠优先 |
| 直接子卡内混有题干、作答所需内容，或无法确认整个分支可安全收起 | 按现有答案遮盖流程处理 |
| MN4、MN5 经典模式或场景折叠能力不可用 | 沿用现有答案遮盖；能力缺失导致本轮切换到遮盖时提示一次 |
| 纯答案脑图绑定，或混合绑定的本题没有直接子卡答案 | 沿用定位和答案窗口 |

按当前题实际绑定和直接子卡结构决定，避免依据学习集的全局绑定盲目折叠。题卡主体和本题作答区须在折叠后仍可用；子卡包含嵌套分支时也须满足整支可隐藏的条件。「脑图书写」继续使用原按钮，无需新增设置项。

## 宿主接口和项目落点

- **折叠写入。** 从已授权的场景面板调用官方 SDK `mn.api('/notes/fold', …)`，使用 `POST`，请求体为 `{ noteIds: [题卡ID], folded: true/false, confirm: true }`。操作作用于父题卡的分支。官方请求契约没有 `topicid`，因此在写入前核对场景窗口及当前学习集，校验回复中返回的学习集和目标结果。文档示例中成功修改的 `changed` 是构造数据，实录只展示无子节点导致的跳过。解析响应体错误与 `skipped`，以重新读取目标的实际状态确认结果。每次仅操作当前目标，目标状态已满足时跳过写入，避免占用撤销栈。[折叠接口](https://dev.marginnote.com.cn/api-reference/卡片与摘录/折叠或展开脑图节点.md)
- **读取与监测。** 优先在当前窗口通过 JSB 按题卡 ID 读取 `mindmapBranchClose`，并检查已附着、仍可见的答案子卡视图。字段读回为收起且无仍可见的子卡视图时，跳过旧模型坐标上的遮盖。先在目标 MN5 版本验证手动展开、场景写入和聚焦后字段能否及时刷新。官方树接口返回 `folded`，但当前公开参考按学习集分页，适合作为定位该字段的文档证据。批量卡片接口中的 `comments[].collapsed` 属于批注。常驻监测只读取当前题卡和当前画布，若无法获得可靠的单卡状态，则切回遮盖。公开场景事件没有分支展开事件，`undo` 等事件只可用于提前触发重新读取。[JSB 字段](https://mn-docs.museday.top/reference/marginnote/mb-book-note/) · [开发者索引](https://dev.marginnote.com.cn/llms.txt) · [脑图读取](https://dev.marginnote.com.cn/api-reference/学习集与卡组/获取学习集脑图.md) · [场景事件](https://dev.marginnote.com.cn/zh/events.md) · [MN Utils API](https://mnaddon.craft.me/mnapi)
- **接入。** 在 [review-mode.ts](../../src/review-mode.ts) 的共用脑图书写导航中协调进题、切题和退出，在 [same-map-practice.ts](../../src/same-map-practice.ts) 复用当前题遮盖、画布校准与同步，在 [plugin.ts](../../src/plugin.ts) 的「查找答案」入口等待展开或答案窗口的结果。在 [sceneTransport.js](../../web/src/lib/sceneTransport.js) 沿用场景就绪检查和现有 WebView ↔ JSB 消息模式，增加只接收当前题卡及目标折叠值的场景请求。沿用公开场景 SDK 和面板授权机制，运行证据取自插件日志与用户设备反馈。

## 一次作答的时序

1. **进入题目。** 确认当前学习集已切换到目标，读取当前折叠状态。分支展开时先折叠，再完成当前题的焦点定位并读回。验证定位是否会重新展开分支。若宿主必须先显示目标才能折叠，或定位会重开答案，需在可能露出答案的阶段先建立可靠的遮盖。折叠和遮盖都无法确认时，保留可重试状态并提示原因。
2. **作答中手动点展开。** 复用会话的同步节奏，发现未获揭晓的答案重新显示时先补遮盖，再发一次折叠请求。一次展开只产生一次折叠写入，收到回执后读回。若写入失败或反复被宿主重开，保留遮盖并停止为本题自动写折叠状态。派发节奏、绘制时机、闪现与撤销行为由真机检查。现有定时同步约为 160 毫秒，不能作为延迟上限或零闪现保证。
3. **查找答案。** 设置为脑图内揭晓且选中答案确属当前题的直接子卡时，本次访问暂停自动折叠，通过场景面板展开，确认分支与答案已显示后移除遮盖。设置为弹窗或选中外部答案时，照常显示答案窗口。展开失败可沿用答案窗口。已有对答案标记只在答案成功显示后更新。返回旧题按新一次访问重新保护，评分规则沿用现有会话。
4. **切题与退出。** 停止旧题的折叠监测并清除会话遮盖。题卡保留当前状态，已经收起的分支保持收起，主动揭晓后展开的分支保持展开。切换学习集或结束会话后，访问代次校验会拦截尚未派发的旧请求。

折叠与主动展开共用串行操作队列，使用窗口、学习集、题卡 ID 和会话代次校验。延迟回复只解决它对应的请求。切题失败保留待重试目标，避免答案状态与题号错位。

## 实施顺序和验收

| 阶段 | 完成条件 |
| --- | --- |
| 宿主验证 | 用插件自身诊断日志和用户操作确认目标 MN5 版本、场景授权、双向折叠写入、按 ID 读回、折叠后聚焦、目标学习集校验与撤销行为。分别记录「写入已确认」和「画布已隐藏」。 |
| 接入与自动化 | 覆盖初始折叠或展开、子卡与混合绑定、纯独立答案、手动展开后的遮盖与再折叠、按设置揭晓、切题、退出后保留分支状态、快速切题及迟到回执、场景失效、超时与失败回退。执行 `pnpm check` 和与脑图书写、做题复习导航、场景通道相关的行为测试。 |
| MN5 真机 | 从展开状态进首题、切题和回看，分别测试原生加号、查看答案、撤销与退出后保留分支状态。用录屏逐帧检查非主动揭晓时是否闪现，同时确认题卡、作答区和布局可用。分别试验纯子卡、混合来源和含作答内容的分支。若进入题目或手动展开时无法稳定遮住答案，则在该宿主条件下保留现有遮盖路径，不启用折叠优先。 |

MN5 5.1.0 日志已确认部分折叠写入和状态读回成功。画布的实际显示时序及撤销仍以目标设备验证为准。
