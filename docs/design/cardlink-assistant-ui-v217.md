# CardLink H1 v2.17｜assistant-ui 对话、工具与设置改版方案

v2.17 源码已接入设置、会话分支、公开运行状态、可恢复提问、只读可视化工具、复习队列和题干相册。模型工具协议 v2 由设备入口显式启用，已有五工具协议仍可用于旧入口和兼容测试。设备端验收与安装包交付单独记录。

实际接入范围与迁移见 [H1 §23](cardlink-harness-h1.md#23-v217-对话工具与设置改版方案)。

上游组件选用 assistant-ui 的官方 Registry 源码。布局仍在 CardLink 的 MarginNote 场景工作台内，保留返回、窗口控件和中文术语。以 v2.17 选定的官方组件为视觉基准，对同一个用途采用一个默认入口。只有 CardLink 特有的业务动作需要组件扩展。通用组件来自官方源码并记录版本及差异；按实际使用入口导入。[官方组件目录][]

## 1. 对话与运行过程

### 1.1 一轮回答的结构

1. 用户消息与发送日期由 Message Pair 和 Day Separator 呈现。
2. 本轮首个可见事件前显示 Typing Indicator。收到执行事件后更新 Run Activity。用户切到别处时，Agent Status 只负责会话入口处的状态提示。状态来自 Harness；界面不生成推理过程或虚构步骤。
3. 每轮只有一个 Run Activity。它展示等待、工具执行和终止等公开运行事件。工具组显示数量，Tool Call 展示单次调用。最终回答由 Markdown Text 显示在活动区之外。
4. Run Activity 提供一个「运行详情」入口。Tool Timeline 在详情内按调用顺序显示工具名、审核状态、执行结果、失败说明和已有耗时。只显示可安全展示的摘要，诊断模式按现行规则显示必要技术字段。审核拒绝和溯源免审分别标记。
5. 多阶段任务才有 Agent Plan。模型可以给出公开的计划文本，步骤完成、跳过和失败必须与运行事件绑定。旧运行缺少时间或计划数据时，省略对应字段。
6. 整轮失败使用 Error State。单次工具失败使用 Tool Error。重试按钮调用 Harness 已定义的重跑或继续操作，只有具备安全的单工具重试路径才显示单工具重试。拒绝、取消、超时和业务失败各用其实际状态。
7. Follow-up Suggestions 默认省略。模型仅在下一步与本轮明显相关、需要用户选择时提出少量建议。点击才发送。缺少本轮继续所需的条件时，使用 Question Flow，避免同一问题在两个入口重复。

历史事件、摘要、工具输出和显示状态以真实运行记录为准。失败或未完成的回答可保留可展示的已有内容。切换会话不能把上一个会话的迟到事件混入当前会话。

### 1.2 分支、编辑与搜索

- 同一会话形成持久的消息分支。编辑某条用户消息保留其之前的共享前缀，从该条消息建立同级版本。重新生成回答从同一条用户消息创建新的回答分支。现有线性历史迁移为初始分支，消息与证据 ID 保持可解析。
- 切换分支不重跑模型。后续提问只使用当前分支的可见祖先消息，以及该分支适用的压缩摘要。不同分支的后续消息、工具结果、图表、提问状态和证据不能交叉。共享前缀中的引用须继续通过源运行、作用域与快照校验。
- Message Actions 提供复制、编辑、重新生成。Message Branches 切换真实的持久分支。Edit Message 保留原问题和原回答。导出按选中的分支生成，保持现行 Markdown 导出的脱敏规则。
- Thread Search 沿用侧栏的跨会话搜索。Conversation Search 搜索当前分支的消息正文，定位到对应消息。搜索与会话切换均走本地数据。删除和彻底删除按现有会话语义处理全部分支及其派生记录。

### 1.3 问题、暂停和恢复

模型通过有界、经校验的交互意图表达本轮缺少哪些必填条件。Option List 承载单选或多选，Question Flow 组织多个步骤。提问文本与选项只是本轮上下文，不能改变授权、工具白名单、模型设置或外部状态。

状态存储在 Harness 侧，不增加第四类 AgentMessage。一个运行同一时刻只允许一个待答问题，绑定 `sessionId`、`branchId`、`runId` 和 `questionId`。等待期间不启动后续模型请求；界面关闭、重新打开或设备重启后可恢复问题和已保存选择。Bridge 校验答案属于当前问题并符合约束。提交以请求 ID 幂等。提交成功后继续同一轮并保持已选模型、审核、证据和快照边界。用户取消后进入已中止状态，迟到答案不得恢复已终结的运行。恢复条件不足时给出明确状态。

## 2. 拟新增的模型工具

现行五个工具保留原名称、参数与语义。v2.17 通过显式的模型工具协议版本增加下表两项。两项均经过 PolicyGuard，按现有只读审核规则进入 Reviewer 或溯源免审。模型只能访问白名单中注册的 Schema。调用结果仍使用现行 ToolEnvelope，运行和审计与调用 ID 对应。

| 计划名称 | 输入契约 | 输出与授权 |
| --- | --- | --- |
| `renderVisualization` | 由 Schema 区分 `evidence` 和 `concept`。证据型接收组件枚举、已核验来源引用和允许的投影、标题或排序。概念型接收标题、节点和边，以及相互引用的局部 ID。 | 返回受控的组件数据和来源信息，由应用渲染。证据型必须从已核验的同快照工具结果解析字段。概念型标记「模型生成示意图」。 |
| `buildReviewQueue` | 接收可校验的错题范围或现有分类筛选，并接受题量、可选时间预算和受支持的复习目标。规则参数必须明示，不接受任意排序指令或 SQL。 | 返回有序的本地错题引用、入选理由、快照与口径信息。提案作为回答产物保存。模型只能生成队列建议，实际开始复习由用户操作。 |

工具参数草案如下。最终 Schema 拒绝额外字段，按字段用途限制长度、数量和枚举。下面的数值上限是方案初值，实施时要用实际包体和设备验证复核。

```ts
type VisualizationInput =
  | {
      kind: "evidence"
      view: "table" | "chart" | "timeline" | "spec" | "comparison" | "scoreBreakdown"
      evidenceIds: string[] // 1–8 项，解析为本轮允许访问的来源
      fields?: string[] // 最多 12 项，实际字段路径由数据类型的白名单校验
      title?: string
    }
  | {
      kind: "concept"
      view: "diagram" | "flowGraph"
      title: string
      nodes: { id: string; label: string }[] // 最多 64 个，局部 ID 不重复
      edges: { from: string; to: string; label?: string }[] // 最多 128 条，引用现有节点
    }

type ReviewQueueInput = {
  goal: "dueToday" | "strengthenWeak"
  notebookIds?: string[] // 仅缩小当前会话作用域
  categoryPrefix?: string[]
  limit: number // 拟定 1–50
  timeBudgetMinutes?: number // 拟定 1–480，缺少时长依据时反馈无法估算
}
```

可视化产物包含格式版本、视图类型、最小渲染所需数据和来源。证据型额外保留快照与时间。队列产物包含有序记录引用、入选理由、采用的规则、快照与时间，以及预算估算是否可用。两个结果都携带可重新展示的产物引用，复用 ToolEnvelope；失效、超出作用域、未知视图和输入非法分别进入对应错误分支。调用可重复读取已经创建的同一产物。

### 2.1 证据型与概念型可视化

- 证据型图表、表格、时间线、对比卡和评分明细直接读取已验证数据。数值、单位、筛选、时区和缺失状态从对应工具结果取值。数量与统计仍由 StatisticsEngine 或确定性的 SQLite 聚合提供。模型至多选择受支持的字段和视图，不提供可冒充统计的任意数值。
- 以 `snapshotId` 与 `dataAsOf` 锁定数据。只允许当前运行获验证的证据，或符合 H1 已有引用复用条件的同快照证据；越权、已被截断且缺少所需字段、不同快照、未查得明细等情况返回明确的不可用结果。
- 概念图以节点、连线和说明表达解法或结构。只接受结构化的有界数据与安全文本。禁止执行模型生成的 JS、HTML、SQL、Shell 或请求任意外部资源。每种图形声明允许的层级、节点和字段上限，拒绝未知的渲染类型或出站动作。
- 应用保存通过校验的产物描述、渲染所需的最小数据与来源。重开时显示当时的图表。证据不可再读取时标明其状态，不以最新快照替换旧结果。统计、解析结果和模型示意在界面上有明确来源。

### 2.2 复习队列建议

- 复用 H1 现有快照的作用域、题目可用性和到期口径。到期目标剔除已完成复习项，按本地时区的现有到期规则取候选。题目及顺序由确定性规则生成，输出实际采用的筛选和排序，以及每题入选理由。
- 约定的默认排序为到期时间、等级优先级、稳定记录 ID。对另有现成受支持排序的复习目标，复用对应排序函数或 SQL 规则。缺少时长依据时提示「无法估算是否能在预算内完成」，仍可返回按题量限制的队列。清单与计数保持一致，写明筛选为空、超限或题目不可用的情况。
- Schedule Card 展示建议日期、题数与入选理由。用户点击「开始复习」才打开现有复习入口，按生成顺序查看题目。进入前复核卡片是否仍存在和可用，对已失效条目给出反馈。进入动作本身不评分、不改到期时间，复习中的记录由现有评分和完成动作产生。
- 队列是随回答保留的建议。计划时间不创建系统提醒、后台任务或自动修改 Notebook。

### 2.3 审批边界

所有当前工具保持只读，不因 UI 中出现 Approval Card 而新增人工确认。保留现行严格审核、溯源免审和完全允许三档的只读 Reviewer 规则，确定性的权限、作用域、参数、证据和输出限制始终执行。

写入工具留待未来独立修订与验收。届时「完全允许」档跳过模型审核及人工批准，其余档位要求用户批准。确定性拒绝不可人工覆盖。Approval Card 的批准、拒绝和恢复动作只随写入能力启用，当前版本不展示可操作的写入批准控件。

## 3. 引用、题目相册和答案

- Inline Citation 使用可读题名或统计名呈现正文引用。用户点击后通过现有的本地证据权限打开对应详情；未经本轮核验的引用不可跳转。保留来源列表、快照与真实题目的授权检查。
- Image Gallery 作为题目预览。界面只向宿主请求题目题干和题干插图的渲染结果。子评论、答案、批注和手写作答不属于初始预览载荷，不能先请求整卡再靠 CSS 隐藏。预览使用本地受控资源链接，资源归属对应原题。若宿主无法隔离内容，提示预览不可用并提供原题跳转。
- 每张题图下方显示题名、「跳转原题」和「答案」。点击「答案」后才请求已匹配且允许读取的答案，在原图下方独立展开，支持收起。无匹配、资源缺失或超出授权范围时显示对应状态。相册不会主动读取外部图片 URL，不自动把本地图像上传给模型。
- 真实预览隔离所需的 MarginNote API 和宿主效果在实施期按仓库指定三源及目标宿主验证。MN5 场景未启用时保持现有启用指引，验收只依赖插件证据，不能用 MN Bridge 探测。

## 4. 独立 AI 设置页

### 4.1 信息与布局

采用官方 Settings Panel 的源码与样式。以其分区和公共字段控件承载 CardLink 的设置，不开放官方示例里的系统提示词、温度或 Memory 控制。初次与日常共用同一页面。

| 状态或区块 | 默认内容 |
| --- | --- |
| 首次配置 | 依次突出选服务商、填密钥、拉取模型和选模型。模型目录不可用时可手动填写模型名。 |
| 配置完成 | 优先显示已启用的默认助手、审核模型、连接状态，以及编辑入口。角色和状态必须能在窄窗口阅读。 |
| 审核模型 | 默认跟随助手。展开后可独立选模型或选另一连接。跨服务商须分别保存密钥并取得对应角色授权。 |
| 连接高级项 | 自定义 Base URL、协议、保存的连接及密钥状态。展示密钥保存方式与清除入口，密钥明文不回显。 |
| 模型高级项 | 上下文窗口、最大输出 Token、预算预览、按连接与模型保存的费率及诊断。保留上下文压缩和当前口径。 |

### 4.2 编辑、保存与连接

1. 编辑服务商或模型只更新草稿。模型目录查询、手动测试和启用默认模型分别触发。查询只发送认证所需内容。手动测试使用固定测试输入，不带任何错题数据。
2. 「保存并启用」显式提交草稿中的有效配置，本操作不自动测试。未测试配置显示「未验证」，测试成功或失败各显示结果。切换后的验证状态只取对应连接、模型和凭据版本的结果，旋转密钥后老结果不能沿用。校验失败或提交中断时保留原生效配置。
3. 修改同一连接的 Base URL 后以新连接保存。旧的连接 ID、地址与会话绑定保持有效。相同地址的显式密钥更新按同一连接处理。连接标识、角色绑定和地址由 JSB 校验，WebView 只提交受控配置或动作。先保存草稿连接以获取目录或测试时，不能覆盖生效角色或占用原连接的密钥引用。
4. 角色启用作为原子操作。验证连接、模型、协议和凭据归属，提交所更改的默认角色。API Key 短暂进入输入控件，受控提交后清空，请求、响应、日志、会话和测试反馈都不得泄露明文。
5. 首次向某服务商发送错题数据时，沿用 H1 对助手和审核角色分别授权的流程。地址变更的新连接有独立授权。授权被撤销或凭据删除后，关联会话的历史仍可读，后续请求要求按现行流程恢复配置。

### 4.3 默认配置与会话

- 保存的新默认助手只用于新建会话。会话创建时保存选中的连接和模型，包括支持的推理强度。已有会话保留保存时的绑定；迁移时用当时有效默认配置填充缺失绑定，不把未知的历史模型标为已知。
- 聊天输入区的 Model Selector 切换当前会话助手模型，从下一轮生效，重开会话保留。Reasoning Effort 仅在适配器确认当前模型支持时出现，独立于 CardLink 的工具次数、输出上限和上下文预算。已经开始的运行使用其入列配置，历史记录显示当时实际使用的模型和已知强度。
- Context Breakdown 与 Cost Meter 共用输入区右侧入口。常态只显示上下文占用，点开查看构成、用量来源和费用。费率按请求时的快照保留，缺失费率或用量时显示未知。

组件接线前校验目标版本和所需依赖。项目已有手工导入的官方组件优先复用，先核对接口再决定更新。特别核对 `elements-inline-citation` 带来的 Base UI 依赖和现有 Radix 集成。Generative UI 使用项目允许的组件注册表，不启用可执行的通用动作。体积验收记录当前实际交付包与新包的压缩增量、前端启动代价和新增大依赖。

## 6. 契约存储、迁移与实施顺序

| 阶段 | 变更范围 | 完成判据 |
| --- | --- | --- |
| 1. 设置与连接 | 官方设置页、已保存的连接、密钥旋转、角色原子启用、手动测试、验证状态及既有会话绑定迁移 | 草稿不会覆盖已生效配置；默认配置可更改前先锁定已有会话；更改地址产生新连接；不同角色与连接互不混用凭据。 |
| 2. 会话模型与分支 | 会话内助手切换、分支拓扑、运行配置快照、消息操作、搜索 | 旧会话迁移为线性初始分支；编辑及重生成保留历史；重开或切换后只读取同分支上下文。 |
| 3. 运行与等待 | 公开运行事件、运行活动和详情、计划、可恢复提问、错误、后续建议 | 跨重启恢复、幂等提交、取消后的迟到回应，以及每个步骤的真实状态均可验证。 |
| 4. 证据产物与队列 | 工具协议扩展、受控可视化、持久产物、复习计划与启动、题图和答案 | 经过 PolicyGuard，越权引用拒绝，图与证据同快照；队列可交给现有复习入口；题图载荷不含排除内容。 |
| 5. 整体验收 | 桌面与目标宿主、典型视口、无网络、重启恢复、兼容及包体 | 检查通过后再决定是否交付安装包。 |

存储优先新增分支关系、运行模型身份、等待态和产物等派生数据。采用可回滚的 SQLite 事务迁移，保留旧会话、消息、引用 ID、审核和密钥绑定。迁移初始分支时关联既有事件并保持顺序，存储共享前缀以减少重复。分支 ID 明确绑定到运行、提问和产物。压缩摘要只能对适用分支及断点生效。对旧记录中未知的模型、耗时或使用量保持缺失值。

桥接命令按最小权限新增连接草稿、角色启用、会话助手设置、分支查询和修改、问题回复、产物与队列读取等入口。业务键、分页、错误码、长度、状态和大小上限在各阶段的契约测试里冻结。对新增命令和模型工具明确处理旧宿主、未知 Schema、重复请求及中止。方案确认范围不等同于每个传输字段已发布，任何破坏性修订依照 H1 与仓库版本规则另行确认。

## 7. 验收矩阵

| 检查 | 应覆盖的结果 |
| --- | --- |
| 设置和隐私 | 独立连接与角色授权、无自动测试、错误码、密钥不回显及日志脱敏、模型目录失效的人工输入、新默认只用于新会话 |
| 分支与迁移 | 从真实旧 Schema 的实例升级；重开保留新旧回答、证据和次序；分支切换、编辑重生成及删除的正确性；历史运行不被补写成未知模型 |
| 问题与取消 | 等待期间不请求后续模型；通知重复或迟到；重启恢复；提交、超时与取消的确定结果 |
| 工具与证据 | 证据重用按现行条件校验；快照对齐；Guard、Reviewer、参数与审计行为；未注册能力和伪造结果被拒绝；工具结果不暴露执行通道 |
| 呈现与体积 | 官方基础组件依实际场景显示；历史图表不刷新数据；用量与费用有来源；窄面板交互、键盘和减弱动态；压缩包和启动变化实测 |
| 复习及预览 | 入选和顺序可复核；用户触发才打开复习；题图载荷只含题干；答案按需读取；来源定位可用 |
| 设备验证 | MN5 场景启用提示、JSB / SQLite、异步与恢复、CSP 和资源路径，以及真实题图隔离、触控和端侧性能。仅按仓库允许的证据途径验证。 |

源码阶段已完成下述契约的本地实现。真机仍须验证场景 WebView、JSB SQLite、图像资源、原题定位与复习界面的串联。历史记录缺少耗时、模型或计划时保持缺失。官方 Reasoning Effort 当前仅对可按公开协议确认档位的 DeepSeek 原生连接启用。
