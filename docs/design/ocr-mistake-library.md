# 错题 OCR 数据库

## b58 当前契约

- SQLite 是题干、识别结果、人工修订和检索的唯一存储。原有 AI 分析、报告、题目准备及桥接命令已删除，旧 JSON 文件保留在原处。b57 供 SQLite 使用的服务地址和密钥继续从原配置键读取。
- 普通打开、恢复和刷新错题列表只加载列表。有内容查询时先读取已有索引，再通过经典 JSB 的卡片 ID 按需核对错题来源。来源校验信息随同步结果保存在本地 SQLite，后续进程可跳过来源未变且索引有效的卡片。正文变化更新索引，错题移除后清除题目行。指纹相同的题干不重复排队，人工修订继续优先用于检索。
- 图片识别需要在 OCR 数据库确认服务和范围。启用 b58 的「定期自动 OCR」后，已授权范围的新增和变更图片题也会在工作台核对时增量入队。b57 已开启定期 OCR 的用户可关闭后重新开启，以授权工作台内的增量触发。此流程依赖工作台，设备后台的定时执行另行验收。
- 数据库页和错题浏览共用 FTS5 二元组候选索引，规范化大小写、全半角、空白和 LaTeX 的左右定界命令，再核对连续正文。单字符查询在 SQLite 中直接核对。数据库页另支持标题及元数据，错题浏览的「内容」只匹配有效题干。检索结果保留原错题 ID。
- 首次打开 b57 SQLite 时，在事务内更新派生索引，保留题干、人工修订、任务和缓存。逻辑备份格式维持 v1；已更新的 SQLite 文件由 b58 及支持该索引版本的安装包打开。

## 数据与职责

- 错题索引继续管理等级、复习历史与分类；OCR 数据库不写回这些数据。
- 目录固定为 `Application.documentPath/CardLink/ocr-db/v1/cardlink-ocr.sqlite`，只操作插件自己的数据库。使用 SQLite 默认 journal 模式，不启用 WAL。
- `ocr_questions` 保存原生文字、识别文字、人工修订、来源指纹和识别轮次；`ocr_assets` 按实际图片字节 SHA-256 去重；`ocr_question_assets` 保存有序素材关系；`ocr_results` 按素材、引擎、模型和选项保存结果；`ocr_jobs` 保存队列状态、确认时间、租约、重试与远程 ID；`ocr_sync_state` 保存同步范围和游标。
- 所需输入图片保存在素材表内，供中断恢复使用，没有新增每题 JSON 文件。素材和历史结果不会自动清理；b37 支持预览后清理孤立记录与无引用素材，仍保留当前题目及历史任务引用的素材。MinerU ZIP 与解压内容在 `temp/` 下临时保存并清理。
- 旧 `ai/ocr`、`ai/content`、`ai/reports` 不导入、不自动删除。新库既不双读也不双写旧缓存。通用清理即使允许删除保留文件也跳过 `ocr-db/`。

## 来源和隐私

通过已有错题索引确定记录，再用经典 JSB `getNoteById` / `getMediaByHash` 定点读取；不扫描整本学习集。原卡不可读时报告同步失败，不将它视为已删除。只在权威错题索引已移除记录后删除对应库行。

本版只读取原卡正文/摘录图，不包含评论、子卡片或手写。纯文字直接入库；含图题在现有 PreviewFrame 中渲染为 JPEG，长题分片，一题最多 30 张。原图仍通过原卡定位，不声称 OCR 能完整表达电路、几何或波形图。

确认同步时显示服务方、地址和范围。凭据使用既有原生凭据存储，不写入 SQLite；b31 支持从原稿行内输入传入可选 value，未传值时沿用原生安全输入弹窗。普通设置只返回配置状态和掩码；b35 起默认本地持久化。b37 点击编辑或显示时通过限定 OCR 服务的 `aiReadOCRCredential` 读取完整密钥，隐藏、取消、切换服务及离开页面时丢弃网页中的明文。任务配置冻结服务地址与识别选项；数据库中仅保存无凭据配置。服务错误只记录分类后的说明。

## 同步、队列与修订

同步每题让出事件循环，逐题保存游标。重新进入页面点击「继续队列」会恢复未完成同步。识别按素材串行执行；所有 SQL 操作同步完成，事务不跨网络 await。任务领取在 SQLite 事务内完成，租约 180 秒并随阶段更新；旧租约不能提交新任务的正文。

来源指纹基于实际渲染正文（含图片数据），与等级和复习时间无关。原题变化或主动重识别会产生新的识别轮次；原题改回旧内容也不会复活历史任务。默认增量模式下，十次未变化同步、修改等级或仅切换服务不会重新识别已就绪题目；b37 可明确关闭增量模式，让后续同步重新识别所有范围内图片题。

识别完成再次读取来源，只有来源指纹和识别轮次仍匹配才更新有效正文与 FTS。人工修订优先，可显式恢复识别文本；编辑使用 revision 检查，拒绝过期覆盖。

MinerU 创建批次后先持久化 remote ID，再上传；恢复先查询原批次。GLM 请求结果不确定时进入待确认状态，不自动重复 POST。供应商 GET 网络错误/限流最多尝试 3 次，指数退避。b37 可另启用失败任务自动重试，仅对结果确定的限流、网络或超时任务退避重试，累计失败 3 次停止；结果不确定、参数、格式和凭据错误不自动重提。用户重试也有退避。上传未完成的 MinerU 批次可能继续等待文件，此时需单题重新识别。暂停停止后续调度；取消撤销待处理任务，不能撤回服务方已接收的请求。

## 搜索与界面

FTS5 外部内容表使用 unicode61，中文另写连续 2-gram。用户查询转换成由程序生成的 token，并通过参数绑定传入；候选再用归一化原文连续匹配。筛选、匹配先于分页，每页至多 50 条；全文不会一次性返回给列表。单字查询要求学习集范围。原始 LaTeX 保留，搜索表示只做有限规范化，不做数学等价式判断。

入口仅位于设置 → 错题管理；总览不提供 OCR 或停用 AI 总结入口，错题管理也隐藏旧 AI 分析行。管理页复用插件蓝色令牌、ExportSelect、PreviewFrame 与 SvgSwitch，按窗口全宽布局，顶部返回随滚动固定；暂停/继续/取消队列控制仅位于概览的“需要处理”上方，任务与设置页不重复显示。页面支持范围/状态筛选、全文搜索、正文修订、定位、单题重识别、任务恢复及数据库诊断。原 AI 配置页不再挂载；原生分析/预览/定期调度/旧准备入口同时禁用。

## 桥接接口

命令经现有 WebBridgeCommands → rails-core → ocrBridge：

| 命令 | 用途 |
| --- | --- |
| ocrDbGetStats | 题目/任务状态数量、同步进度 |
| ocrDbCapabilities | 插件内参数绑定、回滚、完整性、FTS 一致性和关闭重开诊断 |
| ocrDbSync | engine、notebookId 或单题 recordId、consent；返回同步 jobId |
| ocrDbNext | 恢复同步或领取一个准备/识别任务；渲染任务返回 jobId、lease、html |
| ocrDbSubmitImages / ocrDbFailCapture | 按租约提交截图或记录准备失败 |
| ocrDbSearch | query、notebookId、status、offset、limit，返回分页摘要 |
| ocrDbGetQuestion / ocrDbEditQuestion | 全文及当前来源指纹、识别轮次的任务详情；revision 保护人工修订 |
| ocrDbRetryQuestion | recordId、generation、confirmed、onlyFailed；事务内重试当前轮次的失败/不确定/取消任务，onlyFailed 仅选失败，不确定请求统一确认 |
| ocrDbRetry / ocrDbCancel | 单项重试或取消队列；不确定请求须 confirmed |
| ocrDbPause / ocrDbResume | 暂停或恢复同步及领取；暂停保留游标，释放截图租约，远程任务恢复使用原 ID |
| ocrDbRebuildSearch | 仅重建索引，不请求 OCR |
| ocrDbGetPreferences / ocrDbSavePreferences | 持久化增量、自动重试及定期 OCR 设置；关闭增量或开启/修改定期范围需 consent |
| ocrDbAutoTick | OCR 页面打开时检查到期；持久化服务、范围、间隔和下次执行时间，服务配置改变后停止并要求重新确认 |
| ocrDbBackup | 创建包含图片与历史任务的 JSON 逻辑备份并打开系统保存面板；不宣称外部保存完成 |
| ocrDbSelectBackup / ocrDbImportBackup | 原生选文件，返回预览与临时 token；confirmed 后事务替换，不回传整库至网页 |
| ocrDbPreviewCleanup / ocrDbCleanup | 预览及确认清理不在权威错题索引的记录和无引用素材 |

SQL 定义在 `src/ocr-store.ts`，版本为 1，拒绝未来 schema。原生连接在 `src/ocr-native.ts`，只使用数组绑定，不拼接用户值。任何结果集均 finally 关闭。运行中的任务不允许执行关闭重开的诊断。

b33 根据 b32 真机日志修正 busy_timeout 初始化：赋值会返回结果行，必须使用查询接口而非更新接口；失败时释放连接。页面服务设置与数据库统计独立加载，数据库不可用不应导致凭据引用丢失或阻断密钥配置。

b34 的 GLM `file` 参数发送完整图片 Data URI（含 MIME 和 base64 前缀），不截成裸 Base64。服务错误保留数值 HTTP 状态与经过校验的纯数字服务码供分类和显示，不将原始响应报文写入任务错误。已失败任务可手动重试现有图片，无需重新同步。

## b36 单题重试与请求诊断

单题详情仅显示当前来源指纹和识别轮次的任务，历史任务继续保留。界面合并为一个“重试识别”按钮与一条最新错误；没有可重试任务时提供“重新识别”。未改动正文时禁用保存。不确定提交只在用户点击重试后统一确认一次，确认前不发请求。重试复用现有素材和任务，不清除人工修订；过期轮次拒绝重试。批量“重试失败”跳过不确定提交。

GLM 请求按官方文档及 [官方 SDK](https://github.com/zai-org/GLM-OCR/blob/main/glmocr/maas_client.py) 核对：POST `/layout_parsing`、Bearer、JSON `model` 与完整图片 Data URI `file`，解析 `md_results` / `layout_details`。400/422 显示参数拒绝，413/415 显示格式错误；不再将所有 400 错误直接归为图片格式。不确定结果保留超时或 HTTP 分类信息。

开启插件调试时，OCR 日志记录任务、轮次、引擎、MIME、字节数、请求方法、HTTP 状态、纯数字服务码及耗时，不记录密钥、图片或原始响应。桌面联通测试调用真实 provider 和共享 HTTP 组装，仅模拟原生网络回调；未调用真实付费接口，不能据此宣称真机识别成功。

## b37 识别行为与维护

识别引擎持久保存至既有 AI 设置，独立 OCR 行为保存在 `mn4-answer-matcher.ocr.preferences.v1`。定期 OCR 可选每小时、6 小时或每天；开启时明确服务、范围及费用，冻结无密钥配置。计时检查仅在 OCR 管理页打开且页面可见时执行；首次进入会检查到期，离开暂停，不承诺宿主后台执行。手动暂停后同一次页面内不再自动启动。导入后停用定期设置。

备份包含题目、图片、关系、识别结果和任务，不包含密钥、全局设置或同步游标。保存在库目录 `backups/`，同时调用系统保存面板。导入通过经典 JSB `Application.openFileWithUTIs` 等待回调，预览后确认整库替换；schema、字段、关联或 FTS 校验失败则整笔回滚。导入保留人工文本、远程 ID 和历史结果，清除租约；非终态任务转为取消或待确认，不自动上传。备份/导入/清理要求没有运行中的网络、同步和截图任务。孤立清理先以事务回滚预览数量，确认后重新按当前错题索引判断；不删除仍被题目关系或历史任务引用的素材。SQLite 删除后的空间可供后续写入复用，不保证文件立即缩小。

## 验证与限制

### b35 管理界面与凭据

页面采用概览、任务、设置三个内部页签，b35 根据用户最新要求回归插件现有 UI 风格和自适应全宽，取消固定640px原型窗口。返回保持可见；b36 将队列控制移至概览“需要处理”上方，范围/地址与维护操作有明确按钮。b37 已接通识别行为开关、定期 OCR、备份导入与孤立记录清理。页签切换保持队列实例；离开页面暂停同步及后续领取。已发给服务方的请求不能撤回；GLM 当前响应可正常保存，MinerU 当前上传/查询完成后暂停后续轮询。取消后迟到响应不修改题目。

密钥默认使用 local 持久化。进入管理页时，已配置的 session 凭据通过 aiSetCredential 的 persistExisting 参数在原生端转存本地，不回传秘密值。b37 密钥栏右侧仅两个等尺寸图标按钮：编辑和显示/隐藏；编辑时替换为对勾与取消 X，输入框内侧 X 清空草稿，确认后才持久删除。失焦不保存，取消保留旧值，默认以掩码作为实际只读值显示，不再用“已配置”占位符或附加说明文字。没有将凭据写入 OCR SQLite。

桌面 SQLite 行为、模拟桥接及供应商协议测试不等于 MN4 真机验证。真实数组绑定、中文检索性能、App 完全退出事务恢复、多个宿主运行时并行及收费服务全链路尚未验证。缺少对应桥接方法时明确报错，不能宣称已通过 P0 真机验收。同步游标和 OCR 任务持久化；页面重新进入后由用户继续，后台无限运行不在保证范围。

本轮不包含旧缓存迁移、跨设备自动同步、RAG 或 AI 分析恢复。b37 的备份是带格式与 schema 标记的 JSON 逻辑快照，不能直接导入任意 SQLite 文件。正式错题浏览输入框仍保持原搜索契约，全文搜索位于 OCR 数据库页。
