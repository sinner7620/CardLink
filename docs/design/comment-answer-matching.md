# 子卡片 / 子评论答案匹配方案

日期：2026-10-16。状态：可行性评估与建议方案，尚未实现或真机验收。

## 结论与前提

官方场景 API 已提供评论读取与原生折叠/展开，核心流程可行。开启 CardLink 场景功能只是前提，还需宿主实际允许创建场景面板，并允许调用评论读写路由。不能仅凭已有版本门槛或设置开关判断支持。

“第三种”指第三类答案来源：答案脑图、直接子卡片、题卡内评论；不向标题/父节点顺序/正则三种跨卡匹配规则中再塞一条规则。评论答案通过所属题卡直接关联，不需标题匹配。

## 建议交互

1. 答案配置将“子卡片”入口改为“子卡片 / 子评论”，展开选择“仅子卡片”“仅子评论”“子卡片与子评论”。旧绑定默认仅子卡片，保留题目颜色筛选。
2. 评论来源默认规则建议为“全部普通内容评论”，明确提示适用于正文为题目、评论为答案的卡片。提供逐题“选择答案评论”，用于题干补充与答案混排的卡片；不能自动判断任意评论的语义。
3. 排除纯标签、空内容和能明确识别的作答纸/练习批注。普通手写图片无法仅凭类型判断是标准答案还是自己的作答，需要用户选择。图片评论不能因为 text 为空就被排除。
4. 快捷区增加“一键折叠答案评论”，作用于本次已选题目；未选题时要求先选择范围。按钮附近展示题目数，完成后报告成功、跳过、失败数。折叠仅作用于被认定为答案的评论，保留题干正文与其他评论。
5. 开始做题时先折叠本轮目标评论，再进入做题；纯评论题目不再因为“没有直接子卡片”被拒绝。子卡片答案继续使用现有遮盖。
6. 点击“查找答案”，仅展开当前题目的答案评论。下一题保持隐藏；同一题在本轮返回时保留已揭晓状态，重新开始一轮重新折叠。提供当前题“收起答案”。
7. 仅评论模式直接原位展开；两种来源同时启用时，原位展示动作同时展开评论与解除该题子卡遮盖。窗口展示时按来源分组，不能把整道题伪装成一张答案卡。混合匹配维持本地来源在前、答案脑图在后的原则。

折叠是宿主保存的评论状态，不是临时 CSS。第一版结束做题保留最后状态，界面说明这一点；不默认承诺自动恢复或跨设备隔离。引用卡的共享评论可能影响原卡与其他引用处。

## 已核实的接口与边界

- `GET /notes/{noteid}/comments`：返回完整评论投影及顶层 revision；包含作答纸，序号从 1 起，没有文字的评论也占序号。
- `POST /notes/{noteid}/comments/fold`：传 targets、collapsed、expectedRevision；一次最多 200 条评论，且属于同一请求题卡。不是一次折叠 200 张卡。
- targets 优先用 `{ownerNoteId, commentId}`。旧评论的 commentId 可能为 null，首次可用本次读取的 index；不把旧 index 当作长期身份。写后重读，不能假设宿主必然补齐 ID。
- 每次写入判断 error 与 persisted，并核对返回/重读状态。409 COMMENT_CHANGED 后重读与重新解析目标，不能直接重放旧序号。超时先读状态，不盲目重复写。
- 引用卡按当前显示卡的 noteid 发起，宿主负责写入实际 ownerNoteId。批量处理共享评论时按实际身份去重。
- 多张题卡没有本方案已确认的整体事务；逐卡处理、明确部分成功。单卡超 200 条时分批，每批使用最新 revision。
- 运行时读取 capabilities/guide；路由存在仍需处理面板白名单拒绝。能力不足时明确禁用评论折叠，不显示成功提示。

推荐将来源解析、评论读取/写入、做题显示状态分开。同步的旧卡片匹配函数不直接承担异步评论请求；上层组合卡片与评论候选，统一服务查找与详情。异步返回要核对学习集、题卡和本轮操作身份，切题后不能更新新题。

## 显示风险与实施顺序

官方 render 文档只承诺合成整卡长图，没有承诺遵循评论 collapsed 或只渲染指定评论。因此不能因为原生折叠成功，就认定 PNG 也不会泄露答案。

第一阶段先完成最小真机验证：文字、图片、手写、链接评论分别读取→折叠→重读→原生查看→展开；检查共享评论与旧无 ID 评论，同时观察脑图布局刷新、撤销和 PNG 输出。验证通过后优先交付原生原位揭晓。

若整卡 PNG 忽略折叠，评论练习中的题目预览改为只渲染正文/摘录与未隐藏内容；需要利用结构化内容和媒体接口验证图文映射。不用遮挡整张 PNG 的猜测坐标，也不能继续显示包含隐藏答案的整卡截图。仅评论答案窗口要有独立的评论内容投影，作为第二阶段完善项。

第三阶段覆盖复习详情、AI、导出与答案候选记忆。初版范围应清楚区分“原位展开已支持”和“所有答案消费者已支持”，不能把前者描述为后者。
