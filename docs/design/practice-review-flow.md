# 做题与复习的实际流程

此页以当前代码为准，区分会话工具条、宿主批注窗口、页面直接评分。b72 修正了实际 Rails 回调缺失、标错按钮误绑下一题、仅展开反馈就提示保存，以及失败后反馈区不恢复的问题。自动回归不代表 MarginNote 真机触控已经验收。

## 三种入口与两种目的

“做题”从所选题卡建立本轮队列，可选择脑图、原生批注、宿主手写会话。“复习”从待复习队列启动；固定曲线有不会／不熟／掌握三个等级，智能复习有不会／不熟／良好／掌握四个等级。智能复习需要对应功能开启，属于单独入口。

批注启动检查宿主作答判定和当前模板配置；手写启动检查宿主专用笔迹层能力。不可用时说明原因并停止，不假定能保存。

脑图／手写做题保留独立的“下一题”和“标记错题”；下一题使用箭头，题目已有错题记录时反馈按钮使用对勾并显示“复习反馈”。批注做题不显示工具条“下一题”，只保留标错／反馈主动作；切题由宿主批注窗口的“下一题／做完了”保存回执驱动。批注另有历史入口，因此批注、脑图、手写做题均为八个主控；复习不增加标错入口，批注八个、脑图／手写七个。

## 做题流程

| 题目与方式 | 点击标错／复习反馈 | 工具条下一题或宿主保存 | 何时真正完成 |
| --- | --- | --- | --- |
| 普通题·脑图 | 仅展开本题等级和错因，点等级后主动创建错题记录 | 无主动评分时直接切题，不标错 | 本轮记完成；处于队列末项时结算 |
| 普通题·批注 | 仅展开反馈，不保存、不提示、不切题；可选错因再选等级 | 工具条无下一题；在宿主右上角保存后，有主动等级按该等级标错，否则默认原生“会了” | 原生判定及主动标错所需写入成功后切题并打开下一题批注；默认会了不创建 CardLink 错题 |
| 普通题·手写会话 | 仅展开反馈，直到选择等级才保存当前笔迹并主动标错 | 未主动评分时先保存专用层、结束当前尝试，再直接切题，不标错 | 保存及结束确认后记完成；不伪造普通批注判定 |
| 已有错题·脑图 | 展开复习反馈，选择等级更新原记录 | 直接记本轮完成并切题，不要求评分、不改复习记录；主动提交失败时重试所选等级 | 下一题完成本轮题目；主动反馈另更新原复习历史和计划 |
| 已有错题·批注 | 主动展开反馈；选择等级后等待宿主批注保存，再更新原记录 | 工具条无下一题；未选等级时宿主保存后默认原生“会了”，直接切题，不弹反馈 | 原生判定成功后完成本轮题目并打开下一题；默认会了不更新错题等级、历史、计划或标签 |
| 已有错题·手写会话 | 主动展开反馈，选等级后保存笔迹并更新原记录 | 未选等级时保存专用层并结束尝试，直接切题，不弹反馈 | 保存及结束确认后完成本轮题目；未主动反馈不更新原复习记录或标签 |

做题入口当前使用固定曲线；只有用户主动选择等级才创建错题或按固定曲线更新已有错题，不会自动转成 FSRS。原生批注做题未选等级时，无论普通题、已有错题还是继续旧作答，都默认原生“会了”并切题／结算；仅打开反馈区或选择错因不算提交等级。默认判定不添加错题／错因标签，也不清除已有标签，不写 CardLink 复习历史和计划。没有新增笔迹时仍可按宿主完成事件推进，但只对实际确认的作答身份写原生判定。智能复习由智能复习入口单独启动。

## 复习流程

1. 脑图复习：定位题目并按设置遮盖答案。下一题展开本题反馈，选择等级后保存并推进；已于本日完成的题目可直接推进。脑图仍允许明确跳过，跳过不写等级。
2. 原生批注复习：打开本次作答。工具条下一题只展开反馈并静默同步窗口状态，未选等级不提示保存、不评分、不切题。选择等级时，若编辑器仍打开，才提示“已选择等级，请点批注窗口右上角‘下一题’保存后继续”。宿主保存关闭后提交原生判定与复习记录，成功后推进。
3. 手写会话复习：下一题只展开反馈。选择等级后保存当前专用层、确认快照和结束尝试，随后写复习成绩并推进；保存失败不先改成绩。

也可以先在宿主批注窗口点下一题／做完了，再选择等级：保存回执到达后工具条展开反馈，保留当前题，不会替用户评分。批注和手写复习没有跳过等级入口。

固定曲线根据所选等级更新间隔及历史；连续掌握时可结束该题自动复习。智能复习按四档反馈交给 FSRS 调度，显示预计间隔并记录对应事件。两者都在持久化成功后推进。

## 错因怎样选择和提交

反馈区中竖排上侧为等级、下侧为错因；横排左侧等级、右侧错因。单击选中一项主要错因，再点同一项取消。可以先选错因再点等级；原生批注等级已预选、尚在等保存时，也可更改或取消错因。不会／不熟携带选中的错因，良好／掌握不携带。未选错因仍提交等级。

脑图／手写提供六个标准错因；原生批注遵循模板允许的清单，最多六项。旧模板少于六项时显示实际数量，新转换模板有六项标准错因。CardLink 固定曲线历史保存本次 key 和 label；智能复习内置错因保存标准键，模板自定义项保存为备注。

错因点击通过正式 `rails-core → WebAddon` 原生方法表注册。b69～b71 仅在另一条入口注册了该动作，实际安装包缺失该回调；b72 已补齐，并增加交付包方法表检查。

## 新批注、旧批注和返回旧题

默认每次开始本题作答请求新建原生练习批注，包括返回之前的题目。历史窗口选择“从当前批注继续”时明确复用指定批注；如果宿主仍返回已有批注，仅在确认该 commentId 属于当前题卡、当前学习集及正式 CardLink 插件时接续。做题未主动选择等级时仍默认会了并推进，复习仍须选择等级。旧普通批注及身份不匹配批注不能冒充原生练习批注继续评分；关闭回执仍保留实际 saved/commentId，但不执行排队等级或推进。

复习中继续旧原生作答后，即使没有新增笔迹，也仍要求本次复习等级，并把反馈提交到该 commentId。做题中继续旧作答不强制等级，未主动选择时默认原生会了；有主动选择时提交所选等级。原生下一题／做完了代表编辑完成，不冒充用户主动标错。

本轮已完成反馈的题目切走后返回，仍按正常导航打开批注窗口，但不自动展开反馈，保留上次等级、错因及对应作答身份的成功快照。宿主下一题／做完了保存后正常推进并打开下一题批注，不重复评分；复习工具条下一题同样等待当前窗口保存。此状态仅在当前会话内保存，新一轮不继承。做题可主动点击“复习反馈”，复习可从序号菜单选择“查看／修改本题反馈”，即使正在书写也可手动展开上次等级和错因；只有点击等级才发起新反馈，仍需当前批注保存确认后提交。每次导航默认新建作答，不自动把旧等级写入新批注；序号菜单重新选择当前题或反馈区“重新打开批注窗口”也可新建作答。历史明确续写在复习中仍需本次评分，做题中则只有主动选择等级才写错题反馈，未选择时默认会了并继续。保存失败不覆盖上次成功结果，不把失败当作完成。

### 历史作答排队续写（b78）

在当前原生批注仍打开，或已经保存但尚未完成等级反馈时，历史窗口选择“从当前批注继续”会把所选原生练习批注加入本题的待续写队列并关闭历史查看层。当前是尚未反馈的新批注时，点击下一题先等待宿主关闭回执：未保存内容的空白新板直接进入历史，不写原生判定或 CardLink 复习成绩；新板已保存内容则询问“保存当前批注并反馈／丢弃当前新批注”。选择保存后必须完成主动等级反馈再进入历史（做题也不默认会了绕过此确认）；选择丢弃只删除通过打开前批注集合、会话令牌及原生归属确认的本次新批注，读回确认后直接续写。取消询问保留新批注及任务，可点下一题重新选择。由于公开场景 API 没有编辑器未保存笔迹查询与取消接口，该询问发生在宿主保存关闭之后；“丢弃”是撤去本次保存的批注，而非在编辑器内部取消。

已经续写旧批注时不套用新板丢弃逻辑，仍按当前目的正常完成：复习须本次等级，做题未主动选等级则默认会了。已完成本轮反馈的新板也不再询问或重评。随后处理下一份历史或返回原题目队列，末题也先处理续写再结算。

多份历史按选择顺序执行，同一待续写批注不重复加入；选择正在续写的批注不重复排队。续写作为当前题目的额外作答，不增加题目数或改题号，不伪造新批注。普通批注仍只能查看。主动跳题、重选当前题或退出取消尚未执行的续写，关闭当前批注但未完成正常保存/反馈不会自动切入历史。

明确没有打开续写窗口时保留队首任务，恢复已完成反馈的状态，点击“下一题”重试不会再次提交当前成绩；打开结果不确定时等待该任务的关闭回执，不盲目重开。排队仅保留于当前做题/复习会话，不跨退出或重启持久化。宿主仍可能在保存后关闭编辑器再打开历史，本功能省去用户手动关闭和重选的步骤，不保证原生窗口无缝复用。

## 下一题、末题、上一题、索引和退出

- 脑图做题的普通题与已有错题都可直接下一题；批注做题仅保留反馈按钮，宿主保存后未主动选等级则默认会了并切题开窗；宿主手写做题未选等级也保存后直接推进。复习仍需本次等级，本轮已反馈题回看不重复评分。
- 队列末项遵守同样的保存规则：脑图做题无需评分即可结算，批注做题未选等级时保存及默认判定完成后结算，手写做题确认保存及结束后结算；未反馈的复习题必须等级提交成功后结算，做题主动所选等级也须写入成功。本轮已反馈题不重复评分。结算显示队列数、完成数和用时，重复回执不重复结算。批注做题默认“会了”经宿主确认后，将本份作答记为“已对答案”（用户约定的默认反馈）；失败时不写此状态。该状态按 commentId 保存，新轮请求新作答，不带旧 ID、不继承旧状态，明确历史续写仍使用指定旧 ID。
- 上一题或序号／分类跳题属于显式导航，不替用户评分。编辑器尚未关闭时等待保存回执，再按最后一次导航目标执行；未评价的题目不记完成。
- 明确点击退出也不替用户选择等级；批注先等保存关闭，手写先确认会话结束，再退出并显示本轮统计。
- 如果手动跳到了队列末项，完成末项后会结束当前队列；统计保留实际完成数量，不把中间未完成题目补成已完成。
- 查找答案只打开答案并记录本次是否成功显示过答案，不自动选等级。脑图复习的答案窗口评分属于同一复习记录；批注和手写通过工具条反馈。

## 保存失败和回执异常

任一原生判定、笔迹保存或复习记录写入失败时保留本题，不因失败切题或结算。主动选择的普通题等级提交失败后可在反馈区重试原等级，不把它覆盖为默认会了；批注做题无工具条下一题。原生判定已经成功但本地写入失败，重试不重复提交相同原生判定。

关闭回执丢失时使用反馈区的“批注窗口已关闭？恢复操作”，先查询已保存回执，必要时显式确认窗口已关闭；未知状态不自动当作保存完成。收到关闭回执后，反馈区改为“重新打开批注窗口”，明确新建作答，不伪造释放回执或自动写入等级。横排的恢复／重开入口独占底部整行，避免双栏宽度截断。重复、旧题或过期 token 回执不能重复推进。手写会话状态不明时保存重试沿用对应会话身份，不随意新建。

## 没有进入会话的页面评分

待复习网页直接点等级，与上述工具条会话是独立入口：固定曲线目前仍走主要错因选择弹窗，允许跳过错因保存，取消则不提交；智能网页不会／不熟会展开内联错因编辑区，可多选及备注，点保存反馈后提交，取消则不提交。这里没有“下一题”或批注窗口保存步骤。卡片命令「标错」使用目标卡片侧边的原生页，点击等级立即保存；不会／不熟随后展开可选错因，补写成功关闭且不重复计复测，掌握直接保存关闭并保留旧错因。外部点击或跳过保留已保存等级。原卡片侧边三级快捷反馈与详情侧边单项改级暂时不弹错因，仅保存等级并保留旧错因；普通标记、固定单题／批量复习仍保留原错因选择。这些入口不启动工具条会话，详见[卡片命令侧边页](card-menu-window-glass.md#卡片命令侧边反馈页2026-11-02)。

## 已验证与未验证

本轮自动回归覆盖三种书写方式×普通做题／复习的逐题到末题流程、已有错题、智能复习、旧原生作答、失败重试、正式原生按钮分发，以及交付包原生方法表。仍未连接 MarginNote 设备，真实触摸命中、宿主批注保存回执时序、原生窗口可见性和实际数据持久化尚未真机验收。

## 筛选和场景窗口

待复习的自定义来源或等级筛选启用后，筛选角标显示当前到期状态页中实际列表题数，切换页签及筛选会更新，零显示为 0；重置所有自定义筛选后隐藏。

场景锁透从 b71 起按用户提供的 FuckShitOpacity v0.2.1 原生流程执行：从当前窗口视图树找 WKWebView 的直接 UIView 父容器，只考虑可见、alpha 0.51～0.71、尺寸至少 280×180 的目标。唯一候选时先恢复 layer.opacity，再以 30Hz 检查该容器；图层不可读或写回失败时，仅在 setAlpha 可调用时尝试。稳定后以图层为准，不因 alpha 仍读为 0.6 而反复写入。没有候选时每秒检测一次；收起暂停，销毁停止。

这一规则不依赖 URL、网页脚本执行或页面标识，与参考插件一样也不识别插件归属。多个符合条件的半透明网页容器同时出现时不修改任何一个；只有一个其他插件的半透明网页容器时，也可能被该规则选中。因此不能将此功能描述为已证明“只修改 CardLink”。宿主原生视图匹配与实际视觉效果仍需设备确认。控制器保留最近锁透状态，并写控制台／调试日志。

工具条展开和拖动恢复从 b70 起由同一帧时钟同步更新外框及内容裁切坐标，不再串行执行外壳、淡入和交接动画。每帧通过 Core Animation 事务关闭隐式动画，减少动态效果时直接切换至最终状态。

模板转换网页在用户浏览器中解包与重打包，保留原模板布局、素材及其他插件；CardLink 配置改为六错因并嵌入所选正式通道安装包。转换不能替代宿主的能力检测；原生作答与手写仍依赖实际宿主能力。


## 原题错因标签（b77）

普通标错、批量标错和固定复习反馈会在原卡片写入当前反馈的 `错因_<名称>` 标签，例如 `#错因_计算失误`；重新选择错因替换旧错因，未选错因的下一次反馈清除旧错因标签，历史中的错因快照不改写。卡片命令即时等级保存与侧边等级快捷反馈例外：只改等级时保留已有错因标签，但新历史不继承旧错因；卡片面板选错因时补写本次历史并替换原卡错因，不额外推进次数或计划。自定义名称去除标签分隔字符、空白替换为下划线。`错因_` 是托管前缀，不计为用户自定义分类，单独保留错因标签不能恢复错题身份。取消错题时移除托管错因与等级标签，保留用户标签。

FSRS 调试复习按最新事件的错因同步标签（允许多项）；修改错因时同步，暂停不改标签。只改卡片错因标签，不改固定曲线等级、历史或进度。内置错因使用既有六项名称；原生模板自定义错因通过该事件的“错因：”备注投影名称。

只在用户实际写入／反馈时更新标签，不启动全库回填；既有历史记录保持原样。标签回读包含错因验证，不能只写入等级就宣称整次反馈成功。
