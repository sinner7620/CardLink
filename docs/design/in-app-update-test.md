# CardLink 软件内更新与生效测试

## 当前行为验收（b83 起）

先安装 b83，再连续点击版本号 5 次开启调试模式，开启「调试安装包下载」和「自动安装更新」。开关只保存设置，不应开始检查或下载。待后续激活或返回前台触发自动检查，且距离上次成功检查已满 12 小时，有更高版本时才自动下载并安装，完成后提示重启。使用实际递增版本验证，重启前应为旧运行版本 / 新磁盘版本，重启后两者均为新版。网站当前目标 b83，本版本不能用同版本包伪造更新。

可单独测试「检查插件更新」的两种按钮：手动安装应打开保存面板而不改磁盘安装版本，保存后自行导入；直接安装应替换文件并提示重启。已安装 b82 后不重复下载。测试不同路径需分别恢复较低版本的起始环境，禁止仅修改清单伪造运行版本。

退出调试模式应清除自动安装开关，重新进入不恢复；下载期间关闭开关或退出调试模式时，完成下载后跳过安装。后续自动检查沿用 12 小时间隔，切换开关不会重置节流；立即重试需手动「检查插件更新」并选择安装方式。旧代码与新版磁盘资源可能混用，安装后应按提示重启，不宣称重启前资源隔离。

下方保留早期 A/B 测试方法，版本与文案以当前测试为准。


## 实现契约

更新器保留 GitHub 优先、Gitee 同版本下载回退；自动检查默认仅提醒，调试模式可开启自动安装。更新弹窗提供「直接安装」「手动安装」，手动方式保存后自行导入。选择「直接安装」后，按 MN Utils 0.2.6 的机制解压、将旧安装目录移到缓存、将新目录移入。安装目标来自宿主传入的 mainPath，不依赖 MN Utils。

只接受 `marginnote.extension.mn4-answer-matcher`，在线更新核对 Release 版本，本地直链要求高于磁盘已安装版本。解压和必要入口文件检查完成后才移动旧目录。替换失败会恢复旧目录；恢复失败明确显示备份位置。旧目录保留在 cachePath/CardLink/updates/<事务>/previous，缓存清理后不保证仍存在。绑定沿用原有备份；文档目录与 UserDefaults 不在替换范围内，不做数据迁移。

插件菜单增加「从链接安装更新」「查看更新状态」。直链只接受 HTTP/HTTPS，使用相同的下载与安装逻辑，无需创建远端 Release；仅使用可信安装包。未调用热重载接口、未强制退出软件。安装成功表示文件替换完成，不代表新代码已加载。

## 真机 A/B 方案

### 官网在线测试（推荐）

通过直链 https://2608204.xyz/downloads/debug/CardLink-v2.4.5-b67.mnaddon 下载起始包 b67 并导入 MarginNote。官网页面保持原样，不展示调试下载或说明；调试清单及安装包仅保留后台静态地址。设置页连续点击版本号 5 次开启调试模式，打开「调试安装包下载」，再点「检查插件更新」。来源应显示「官网调试源（2608204.xyz）」，目标版本为 b71。确认下载并安装后，在调试功能中查看更新状态，并按下方的运行版本/磁盘版本标准验收。

清单为 https://2608204.xyz/updates/debug/releases.json，使用 Release 数组格式；包位于 /downloads/debug/。默认不开启，只有调试模式和下载开关同时开启才会访问。退出调试模式清除下载开关；清单不可用、格式异常、没有更新或附件不属于网站调试目录时，回退 GitHub/Gitee。已选择的官网包下载失败会报错，不伪装成正常源更新。自动检查默认只提醒；调试模式开启「自动安装更新」后会自动下载并安装，完成提示重启。

### 局域网测试（备用）

准备两个正式身份的递增安装包：A = 2.4.5-b65，B = 2.4.5-b66。两包代码行为相同，编译版本不同；运行版本来自编译进代码的 __APP_VERSION__，磁盘版本来自当前 mnaddon.json，不能只改清单模拟 B。

1. 先通过 MarginNote 内置导入安装 A。进入学习集，打开 CardLink 插件菜单的「查看更新状态」，确认运行与磁盘均为 A。记录 MarginNote 版本、系统版本、现有绑定与错题数量，并打开一张答案卡片确认可用。
2. 电脑与 iPad 在同一局域网。在 PowerShell 执行 `python -m http.server 8765 --bind 0.0.0.0 --directory 'E:\iCloudDrive\同步文件夹'`，按需允许系统的局域网防火墙访问。此命令只在测试时运行，结束后 Ctrl+C 停止。
3. 先用 iPad 浏览器确认 `http://<电脑局域网IP>:8765/CardLink-v2.4.5-b66.mnaddon` 可访问。然后在 A 的「从链接安装更新」中输入该地址，点击「下载并安装」。不要先通过 MarginNote 内置导入安装 B，那会绕过待测的目录替换流程。
4. 保持 MarginNote 进程不退出，重新打开插件菜单，查看更新状态。磁盘 B、运行 A = 替换成功但当前代码未重载；两者均 B = 当前调用的新代码已生效。不要用系统插件列表、文件清单或旧窗口标题单独判断热加载。
5. 若仍运行 A，依次记录关闭/重新打开插件面板、关闭/重新打开学习集后的结果。必要时再测试关闭/启用插件；记录具体动作，这只证明对应动作可触发重载，不能归为自动即时生效。最后才测试完整重启。
6. 核对绑定、错题数量和设置保留；测试答案卡片、场景面板、手写（若启用）。若有多个已打开窗口，每个窗口分别检查，避免单窗口成功掩盖旧运行实例。
7. 再安装 B 应提示不高于已安装版本，不再次替换。安装失败时保存错误文本；若自动恢复失败，通过 MarginNote 内置导入重新安装有效包。

| 观测 | 结论 |
| --- | --- |
| 磁盘 A，运行 A，错误提示 | 更新未完成，按错误定位下载/校验/替换阶段 |
| 磁盘 B，运行 A | 文件替换成功，旧代码仍在运行 |
| 未退出进程且运行 B、磁盘 B，功能正常 | 对该宿主版本和所记录动作，免进程重启生效通过 |
| 完整重启后才运行 B | 此直接替换路径未证实支持免重启 |

## 桌面自动验证与限制

执行 `pnpm check`；执行 `pnpm exec tsx --experimental-test-module-mocks --test tests/update-installer.test.ts tests/updater-behavior.test.ts tests/updater.test.ts`。

原生文件系统 mock 覆盖旧目录保留、替换、失败恢复、恢复失败提示、错误身份/版本/缺文件/解压失败拒绝；更新器覆盖在线回退、取消、直链、并发拦截、磁盘/运行版本分离。mock 不证明真机 ZipArchive、文件权限、HTTP 网络策略或宿主热加载能力。完整构建检查打包集成。真机结果另行记录，不把桌面测试当成设备验收。
