# Git 跟踪范围整理

## 目的与实现

按用户要求，使后续提交聚焦插件项目所需文件，排除安装包、临时产物和无关本地资料。

- 根目录采用白名单，接纳源码、资源、测试、构建与发布脚本、依赖清单及锁文件、项目维护文档。
- 保留根目录 `RELEASE_NOTES_v*.md`：GitHub 发布工作流和 Gitee 同步脚本需要读取对应标签的说明，包括预发布说明。
- 明确忽略依赖和构建目录、`.mnaddon`、ZIP、临时参考目录、预览、测试报告、日志及本机配置。
- 本轮只修改 `.gitignore`、`docs/workflow.md` 和本记录。不删除本地文件、不调整 Git 索引、不提交或发布。

## 兼容性与数据影响

插件版本、功能和发布流程不变。新增顶层文件或模块需要显式加入白名单。忽略规则不影响已跟踪文件；已有源码改动和历史删除状态保持原状。项目维护文档继续跟踪，避免丢失接口契约和维护记录。

## 验证与限制

- 检查构建入口及发布工作流引用，确认源码、资源、锁文件、构建脚本、第三方声明和发布说明仍可跟踪。
- 使用 Git 忽略规则检查验证应排除和应保留的路径，并核查是否有已跟踪文件命中新规则。
- 检查本任务差异的空白错误。
- 本轮不涉及运行逻辑，未运行应用测试、构建或 MarginNote 真机验证。此前请求的物理删除未执行，本轮不将忽略视为删除。
