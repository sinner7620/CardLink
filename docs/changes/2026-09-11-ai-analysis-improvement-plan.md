# AI 错题分析实现复核与完善方案

日期：2026-09-11。基于本地工作树，package.json 为 2.4.1。

## 本次范围

重新阅读 AI 原生实现、题目读取、手写渲染、Web 设置/分析/题目准备及相关测试，提出方案。只新增本文档，未实现产品改动，未修改版本、打包或发布；保留其他已有工作树变更。

## 结论

当前已实现“脑图绑定手写 → 整卡截图 → OCR → 本地文本”，尚未实现“题目信息文本 + 手写图片 → 分析模型”。应先打通有来源标识的多模态证据链、修正设置和实际发送行为，再扩展报告功能。

## 优先修复

### P0：输入与控制真实一致

1. **最终模型未收到图片。** callLLM 只接受 prompt 字符串。必须改为接受结构化题目证据，并由服务适配器组装文字与图片。
2. **开关未落实。** privacy.images、privacy.handwriting 和 mineru.policy 有设置 UI，但当前准备/分析流程未按这些值过滤或分流；整卡渲染仍可能包含卡片手写和图片。脑图手写开关只影响新准备任务，关掉后旧 OCR 中的手写文本仍可能被发送。
3. **缓存不校验新鲜度。** readPreparedQuestion 只核验 ready/recordId/questionText；源题、手写或发送范围变化后，旧文本仍可使用。现有 contentFingerprint 未在分析前与当前来源比较。
4. **取消未覆盖请求返回后。** 分析循环检查 cancelled，但等待模型后仍解析并保存；关闭总开关也不主动终止已有任务。需在每次外发前、异步返回后及持久化前检查任务状态。已发出的请求不能声称已撤回。

### P1：报告证据与覆盖范围

1. **引用表大于实际输入。** evidence 在题目读取成功前赋值；items 拼接后整体 slice(0, 120000)，会截断题目，仍保留后续引用。改成按完整题目预算装包，并仅为实际发送证据建立引用表。
2. **缺少作答不等于知道错因。** 当前提示词要求错误模式，但输入可能只有题目、参考答案和掌握等级。报告必须区分观察事实、待确认推测、缺失资料；不得从“不会”直接推断计算失误等具体原因。
3. **准备数量与预检错位。** 预检统计全部 preparedCount，实际只取最近更新的前 300 题，UI 又未展示 preparedCount/analyzableCount。预检应直接复用最终选题与装包逻辑。
4. **过期判定范围不一致。** 保存指纹针对截取后的 records；列表按整个科目计算，超过 300 题时范围不一致。且记录 updatedAt 不能完整代表手写、OCR、模型和提示词变化。
5. **无证据条目仍可显示。** validateEvidence 删除未知编号，但没有剔除或降级证据为空的结论。应同时校验结论的依据类别与实际来源。

### P1：任务和设置体验

- 题目准备依赖设置页组件渲染和推进；离开页面后组件卸载，缺少重新挂接活动任务的入口。下一版至少实现离页提示与返回恢复；统一任务宿主后再考虑持久队列，不声称后台永久运行。
- 设置输入逐字符提交完整 settings，异步返回可能覆盖较新的编辑。使用草稿、保存状态及串行提交/修订号，失败保留草稿。
- 定期执行是面板加载触发的间隔检查：日/周/28 天；hour/weekday/monthday 未参与调度。不能把它呈现为关闭应用后仍准点运行的定时器。

## 目标设计：题目文本与绑定手写一起发送

### 1. 统一题目证据结构

引入 QuestionEvidence，包含 recordId、本地来源定位、sourceFingerprint、题目文本、参考答案、作答材料及 attachments。每个附件保存稳定 ID、角色、来源卡片/媒体 hash、MIME、尺寸、字节数、内容 hash、渲染状态和本地文件路径。不要把 Base64 写入错题主库或报告索引。

附件角色至少区分 question（题图）、reference-answer（参考答案）、student-work（经用户确认的作答）、annotation（批注/未分类手写）。脑图绑定手写不能自动认定全是本人的解题过程，首次可选角色，之后按题保留。

分析输入的逻辑结构：

```text
Q001
题目：原生文字，或该题题图的 OCR 文本
参考答案：选中的答案及来源
复习信息：所选等级和历史
附件 Q001-H1：本题脑图绑定手写，角色为作答过程
[该附件图片内容]
```

本地真实 ID 用于回跳；外发采用 Q/H 引用，不需要把内部 ID 发给模型。图片必须使用服务实际支持的图像字段，不能把 Base64 当普通文本拼入 prompt。

### 2. 分离题目和手写渲染

- 复用现有只读卡片读取器、媒体读取和 PencilKit 渲染内核。
- 原生文字优先直接提取；图片题再 OCR。保留图片附件，不让 OCR 文本替代图形和推导布局。
- 脑图手写单独渲染为可预览 PNG/JPEG；若底图与笔迹是叠加关系，保留组合关系。未知格式标记失败，不一概当 PencilKit。
- 增加明确的渲染完成/失败结果；当前 renderer 将错误变成 HTML 提示，截图流程可能把错误提示也当成功图片上传。
- 限制单图字节数、边长、像素总量和单题图片数；超长笔迹按内容分片。现有 scale 下限为 .5，因此 12000/height 不是可靠的高度硬上限。
- 先做一题端到端验证，再覆盖跨学习集、多附件与批量处理；不要以整张脑图截图替代卡片绑定附件。

### 3. 服务能力与发送策略

把 API 协议（Responses / Chat Completions）与显示名称分离，记录模型是否已验证支持图片、结构化输出及请求预算。当前 type === deepseek 决定协议，其他全部走 Responses，“OpenAI 兼容”标签范围过宽。

用户选用支持图片的配置时，同一题文本和手写图片进入同一次分析请求；纯文本配置明确显示“仅发送识别文字，未发送手写原图”，不静默降级。各服务字段和上限在实现前按所选服务官方文档核对，本次未验证任何在线模型能力。

建议默认单题/选题分析；科目总结先分批生成有证据的题目结论，再汇总薄弱点，保留引用映射与分批覆盖说明。避免将 300 题图片一次塞入请求。

### 4. 缓存与发送范围

题目文本、题图 OCR、作答手写及其 OCR 分开缓存。缓存键包含内容 hash、角色、渲染版本、OCR 引擎/配置；报告输入指纹包含最终选题、附件版本、答案选择、发送选项、模型及提示词版本。

旧整卡 OCR 无法可靠拆开题目与手写来源：保留查看能力，标记为旧混合快照；范围不一致时重新准备，不能沿用旧文本并声称已排除手写。

UI 分清“发送给 OCR”和“发送给分析模型”。每次发送按本次选项生成清单并再次执行过滤，预览使用同一份清单。

## UI 方案

沿用现有工作台，不新增一级导航。错题详情增加“AI 分析”，批量选择增加“分析所选”；总览保留科目总结及最近报告。设置只保留服务、默认发送范围、科目及高级选项。

分析面板有三个阶段：

1. **核对材料**：顶部科目/范围/模型；左侧题目列表及就绪状态；右侧题目文本与手写缩略图，参考答案可展开。底部显示“将发送 N 道题、M 张手写图；K 道缺少作答”，主按钮“开始分析”。未准备/过期题在这里就地处理。
2. **处理任务**：显示“准备 8/12 题 → 分析 → 保存”；列出失败题及原因，支持取消和仅重试失败项。缺关键材料时提供明确的跳过选择，不能静默遗漏。
3. **查看结果**：先显示覆盖范围与简短结论，随后最多三项优先问题；每项包含具体证据、确定性类别和下一步。点击证据在面板内看对应题目与手写，可进一步定位原卡片。历史报告与删除放在报告列表。

宽面板使用列表/内容双栏；窄面板采用列表进入详情，底部主操作保持可见。正文建议 14–16px，辅助文字至少 12px，常用触控按钮建议 44px；统一现有颜色 token，避免依赖当前多处 9–10px 文字。此次仅据 JSX/CSS 评估信息架构和样式，未实测浏览器或设备视觉效果。

## 实施顺序与验收

1. **单题闭环**：证据结构、手写独立渲染、模型图像适配、发送预览；先验证文字与真实绑定图片同请求送达。
2. **可靠性**：策略过滤、缓存失效、取消、渲染错误、引用预算及答案选择；再支持选题批量。
3. **流程与报告**：移动题目准备入口、报告证据布局、OCR 修订与失败重试；最后改造科目分批汇总及定期间隔检查。

自动化验收应检查实际请求体和行为：图片与 Q 编号对应；过滤项不出现在文本/图片中；纯文字无须 OCR；旧混合快照不能绕过范围；取消后不保存；超预算按整题截取；缓存来源变化触发重新准备；无作答不产生确定错因。现有源码匹配测试随新契约更新，不能继续冻结“仅发送文本”的旧行为。

浏览器验收：宽窄面板、长手写、图片加载/绘制失败、离页返回、快速编辑设置及模型等待状态。

MarginNote 真机验收单列：官方桥接接口实际可用性和参数、绑定卡片身份正确、跨学习集/未同步附件、drawing 与底图组合、多附件、绘制质量、内存与真实请求送达。这些未在本次只读复核中验证。
