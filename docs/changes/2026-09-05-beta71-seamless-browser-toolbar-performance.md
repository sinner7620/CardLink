# beta.71：无缝错题本、统一悬浮条与大列表性能

## 问题根因

- 面板主内容统一持有 18px padding 和灰色背景，导致错题本即使去掉卡片边框，列表与详情四周仍存在异色边沟。
- 筛选条位于带 `overflow` 的列表滚动容器中；弹层同时受到裁剪和详情层叠上下文影响。
- 操作控件各自带背景、边框和圆角，批量栏又包一层容器，视觉层级与详情悬浮条不一致。
- 通知使用普通文档流，出现时会改变主内容的纵向起点。
- 大列表在查询、窗口缩放和父组件状态变化时同步过滤并重复渲染全部项目，屏外项目也参与布局与绘制。

## 实现

- 将页面留白的所有权从通用 `main` 下放到总览、待复习、设置和导出页；错题本占满内容区并与详情共用白色底层。
- 将筛选悬浮条提升为列表滚动区的兄弟节点，弹层由该非裁剪节点承载；列表只负责题目滚动。
- 列表和详情操作条统一为单层圆角毛玻璃；移除工具条内部按钮与批量栏的重复卡片装饰，搜索框保留唯一输入边界。
- 详情工具条使用 52% 白色背景与较轻模糊；状态组合在窄详情容器中固定等宽、纵向拼接。
- 定位通知改为 fixed overlay；定位状态机区分 `focused`、`sync-off` 和 `failed`，只在真实未聚焦且同步明确关闭时提示检查开关。
- 悬浮入口停靠边距调整为 18pt，移除贴边露出式负偏移。
- 待复习跨页聚焦使用容器内居中滚动和 1.8 秒高亮，不再依赖浏览器默认的最近边缘滚动。
- 列表项目使用 `React.memo`、`content-visibility` 和 CSS containment，查询改用 `useDeferredValue`，降低长列表重渲染和屏外绘制成本。

## 清理

- 没有新建第二套通知、筛选或跳转逻辑；改动落在原有 App 通知、MistakeBrowser、DueReviewList 和 note-navigation 状态机中。
- 未增加 `!important`，继续使用现有 cascade layer。
