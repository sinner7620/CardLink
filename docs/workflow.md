# 开发、验证与交付

本文件说明 [AGENTS.md](../AGENTS.md) 的执行方式。日常修改、Git 提交、安装包交付是不同阶段；交付安装包才要求版本迭代和完整打包流程。

## 按影响范围验证

| 改动 | 通常需要的验证 | 扩大验证的条件 |
| --- | --- | --- |
| 只读分析 | 核对相关证据，注明未检查范围 | 不运行应用测试或构建 |
| Markdown、规则、历史文档整理 | 内容一致性、涉及链接、`git diff --check` | 修改文档生成程序时按程序影响验证 |
| TypeScript 局部逻辑 | `pnpm check` 和相关行为测试 | 跨模块影响不清时跑完整测试 |
| CSS、Web 交互 | 受影响页面/状态的视觉或交互检查；逻辑变化加相关测试 | Web 导入、资源、打包行为改变时构建；共享样式扩大页面覆盖 |
| 原生桥接、标签写入、存储、更新器 | 相关行为/协议测试，涉及 TS 时做类型检查 | 生命周期、跨学习集写入、迁移及原生 API 行为需要对应真机验证 |
| 依赖、构建链、广泛重构 | `pnpm check`、`pnpm test`、`pnpm build` | 按变化补相关集成或真机验证 |
| 安装包交付 | 最终输入的 check、test、build；包信息和复制哈希 | 正式发布另核对版本标签、发布说明、平台附件 |

相关测试可以直接运行，不必先增加 npm 脚本。例如仅修改详情缓存时：

```powershell
pnpm exec tsx --experimental-test-module-mocks --test tests/review-detail-cache.test.ts
```

选择范围依据调用方、共享协议和受影响行为，不只按文件名。复用本任务中输入未变的成功结果；有新代码、依赖变化或失败证据时再运行受影响检查。不要把验证次数当作质量指标。

## 现有流程的分析（2026-09-11）

- `pnpm check` 是 `tsc --noEmit`，配置包含 `src/**/*.ts` 和 `tests/**/*.ts`；不覆盖所有 Web JSX 和原生 JavaScript，不能代替打包或运行检查。
- `pnpm test` 显式列出 16 个测试文件；`tests/ui-stage2-visual.spec.js` 不在该命令中。测试通过不等于浏览器视觉或 MarginNote 真机通过。
- `pnpm build` 与 `pnpm build:source` 都运行 `node build.mjs`，连续执行两者没有额外验证价值。
- 构建执行 esbuild、Vite、预览资源生成与安装包组装，并检查嵌入脚本闭合序列、原生入口模块名及模块是否存在。这些针对实际产物约束的检查保留。
- 发布 CI 在标签推送或手动触发时执行安装依赖、check、test、build；并非每次普通提交都执行。独立环境验证有价值，保留现有 CI。
- 发布 CI 用版本中的连字符识别 prerelease，故今后预发布采用 `X.Y.Z-bN`，不沿用历史 `2.4.1bN` 写法。历史文件保持原名。
- 本轮未测量各测试耗时，也未评估测试断言质量；不据此删除测试、降低发布覆盖或声称具体性能收益。

## 交付清单

1. 根据当前版本确定未使用的新版本；正式发布按用户决定。更新 `package.json` 与 `RELEASE_NOTES_v<version>.md`。
2. 对最终输入完成 check、test、build。检查包内版本、正式插件 ID 和标题。
3. 将 dist 安装包复制到 `E:\iCloudDrive\同步文件夹\`；记录源文件和复制件的匹配 SHA-256。
4. 如已授权远端发布，标签 `v<version>` 与 package 版本一致，核对 GitHub/Gitee 发布附件。CI 重新构建的包与本地包分别记录来源和哈希；不同构建的文件级哈希不要求天然相等，同一个包的复制件必须一致。
5. 在任务记录中写清实际完成的验证、交付位置及未验证限制。无法验证某项原生行为时，只限制相关结论；若它决定本次交付是否可用，应明确尚未完成该项验收。

## 文档和仓库整理

- [文档索引](README.md) 负责导航；[验收清单](acceptance.md) 按受影响功能选用，不是每轮全量手工测试门槛。
- 历史变更记录、旧发布说明、调查和交接材料用于追溯。旧版本状态、一次性整改计划和当时的测试数量不能自动成为现行约束。
- 发布说明目前由 CI 按根目录文件名读取，保留 `RELEASE_NOTES_v*.md` 的位置。仅为根目录整齐而搬移会破坏发布路径。
- `docs/modules/` 保留现有资料；仅在相关契约改变时更新，不要求为每个新文件再建镜像文档。
- 临时文件、安装包副本、未跟踪的网站目录和已有删除项不自动提交或删除。整理提交只选择本任务的具体路径，不无差别暂存或清理。
- 文档整理本身保留一份任务记录，不修改产品版本、不重建安装包、不改写历史发布记录。
